Ask the audience: who has lost a day to setting up ROS? Who has a laptop with 2 ROS versions?

Key point: containers share the host kernel. They're isolated *processes* (namespaces + cgroups), not a whole emulated machine. That's why they start in a second and cost almost nothing. Consequence: Linux containers need a Linux kernel. Docker Desktop on Mac/Windows hides a Linux VM, which is why we use Linux (and native Docker Engine) today.

Analogy that works: image = ISO / recipe result, container = a running install you can mess up and throw away. Registry = GitHub for images.

Every instruction = a layer; layers are cached by (previous layer + instruction + files copied). The first cache miss rebuilds everything below it. That's why we COPY package.xml before src/. Layers are shared between images, so 10 images FROM ros:jazzy don't take 10x the disk.

DDS discovery uses multicast. On a user network, multicast stays inside the virtual network. With host networking, containers are just processes on the host network. Explain the shared memory trap: with --network host, DDS thinks the peer is on the same host and tries shared memory, but /dev/shm is per-container unless --ipc host. Result: topic list works, echo gets nothing.
